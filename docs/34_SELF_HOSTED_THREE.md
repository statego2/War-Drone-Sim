# Self-hosted Three.js v0.180 — Network Reliability

**Status:** implementation proposal; browser CI and deployment are separate release evidence.

The prior entrypoint loaded the complete Three renderer from a third-party runtime CDN. When that CDN was blocked or unreliable, the portrait game silently fell back to the older Canvas prototype even if GitHub Pages itself was reachable. This is a substantial dependency risk for a browser-first mobile game.

## Change
- The exact upstream **r180** MIT-licensed Three.js WebGL module and its matching core module are vendored under /vendor.
- Both source blobs are unchanged copies of official `mrdoob/three.js` tag r180, except their path in this project. The upstream license is retained in /vendor/THREE_LICENSE.txt and original SPDX headers remain intact.
- The game now imports the local minified ES module via a relative URL; core import is resolved beside it by the browser. This retains Three.js v0.180 public API and WebGL renderer without new external dependencies.
- This **does not promise offline first visits**: GitHub Pages and its files still require initial connectivity. A service worker/PWA requires separate design and testing before offline replays can be claimed.
- Browser smoke explicitly blocks jsDelivr requests and asserts no runtime request went to an external origin. Additional tests check copyright and module pairing.
